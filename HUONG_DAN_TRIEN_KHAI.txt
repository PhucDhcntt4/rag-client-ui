HƯỚNG DẪN TRIỂN KHAI RAG CLIENT UI
===================================

Tài liệu này áp dụng cho kiến trúc hiện tại của dự án: một tiến trình FastAPI
phục vụ cả giao diện và API Client, lấy dữ liệu từ RAG Server rồi dùng Gemini
hoặc OpenAI để tổng hợp câu trả lời.


1. KIẾN TRÚC VẬN HÀNH
---------------------

Luồng chat:

  Trình duyệt
      -> RAG Client Backend + Frontend (port 8100)
          -> RAG Server (mặc định port 8000)
          -> Gemini hoặc OpenAI
      <- câu trả lời, nguồn trích dẫn và URL ảnh được bảo vệ

Nguyên tắc:

- Trình duyệt chỉ gọi RAG Client Backend qua các endpoint /api/*.
- Backend tự gắn Bearer key khi gọi RAG Server.
- Backend gửi ngữ cảnh RAG sang LLM; LLM không tự truy cập RAG Server.
- Frontend không chứa RAG key, Gemini key hoặc OpenAI key.
- Ảnh tài liệu được tải qua proxy /api/rag-assets/{id}; key không lộ ra browser.
- Người dùng chọn Gemini hoặc OpenAI ngay trong ô nhập câu hỏi.
- Hai provider dùng chung system prompt trong backend/app/prompts/answer.txt.
- OpenAI có thêm quy tắc trình bày nguồn và bộ lọc chuỗi trích dẫn quá dài.

Cấu trúc chính:

  rag_client_ui/
  |-- backend/
  |   |-- .env                  cấu hình bí mật, không commit
  |   |-- .env.example          mẫu cấu hình
  |   |-- requirements.txt      dependency Python
  |   |-- app/
  |   |   |-- main.py           khởi tạo FastAPI và phục vụ frontend
  |   |   |-- config.py         đọc/kiểm tra biến môi trường
  |   |   |-- clients/          kết nối RAG và LLM
  |   |   |-- routers/          các endpoint /api/*
  |   |   |-- services/         điều phối truy xuất và trả lời
  |   |   `-- prompts/answer.txt
  |   `-- tests/
  |-- frontend/
  |   |-- index.html
  |   |-- js/
  |   `-- assets/
  |-- README.md
  `-- HUONG_DAN_TRIEN_KHAI.txt

5. TẠO VÀ CẤU HÌNH backend/.env
--------------------------------

Đứng trong thư mục backend.

Windows:

  Copy-Item .env.example .env

Linux:

  cp .env.example .env

Cấu hình đề xuất:

  APP_NAME=RAG Client Backend
  APP_ENV=development
  APP_HOST=127.0.0.1
  APP_PORT=8100
  LOG_LEVEL=INFO

  FRONTEND_ORIGIN=http://127.0.0.1:8100

  DATABASE_URL=postgresql://USER:PASSWORD@HOST:PORT/DATABASE
  RAG_METADATA_SCHEMA=rag_metadata

  AUTH_SECRET_KEY=<CHUOI_NGAU_NHIEN_TOI_THIEU_32_KY_TU>
  AUTH_COOKIE_NAME=mshai_session
  AUTH_TOKEN_EXPIRE_MINUTES=480
  AUTH_COOKIE_SECURE=false

  RAG_BASE_URL=http://127.0.0.1:8000
  RAG_SEARCH_API_KEY=<RAG_SEARCH_KEY_MOI>
  RAG_ADMIN_API_KEY=<RAG_ADMIN_KEY_MOI>
  RAG_TIMEOUT_SECONDS=45
  RAG_TOP_K=10

  PRODUCT_TIMEZONE_OFFSET=+07:00
  PRODUCT_CHAT_PAGE_SIZE=10
  PRODUCT_CANDIDATE_PAGE_SIZE=50

  AI_PROVIDER=gemini
  # AI_FALLBACK_PROVIDER=openai

  GEMINI_API_KEY=<GEMINI_KEY_MOI>
  GEMINI_MODEL=gemini-3.5-flash-lite

  OPENAI_API_KEY=<OPENAI_KEY_MOI>
  OPENAI_MODEL=gpt-4.1-mini

  LLM_TIMEOUT_SECONDS=90

Nếu chỉ có Gemini:

  AI_PROVIDER=gemini
  # AI_FALLBACK_PROVIDER=openai
  GEMINI_API_KEY=<GEMINI_KEY_MOI>
  OPENAI_API_KEY=

Nếu chỉ có OpenAI:

  AI_PROVIDER=openai
  # AI_FALLBACK_PROVIDER=gemini
  OPENAI_API_KEY=<OPENAI_KEY_MOI>
  GEMINI_API_KEY=

Không khai báo AI_FALLBACK_PROVIDER với một provider chưa có API key. Nên comment
cả dòng fallback thay vì để giá trị không hợp lệ.

Ý nghĩa biến:

- APP_ENV: development, production hoặc test.
- APP_HOST/APP_PORT: thông tin host/port dự kiến của ứng dụng. Lệnh Uvicorn vẫn
  phải truyền --host và --port tương ứng.
- FRONTEND_ORIGIN: origin được CORS cho phép; production dùng domain HTTPS thật.
- DATABASE_URL: kết nối PostgreSQL dùng cho tài khoản và nhóm quyền.
- RAG_METADATA_SCHEMA: schema chứa doc_types và document_groups.
- AUTH_SECRET_KEY: khóa ký phiên, phải ngẫu nhiên và dài tối thiểu 32 ký tự.
- AUTH_TOKEN_EXPIRE_MINUTES: thời gian sống của phiên đăng nhập.
- AUTH_COOKIE_SECURE: phải đặt true khi production chạy HTTPS.
- RAG_BASE_URL: URL RAG Server nhìn từ máy/container chạy Client Backend.
- RAG_SEARCH_API_KEY: tìm kiếm knowledge và tải asset.
- RAG_ADMIN_API_KEY: taxonomy, danh sách và chi tiết tài liệu.
- RAG_TOP_K: số kết quả tìm kiếm ban đầu; RAG Server có thể mở rộng nhiều nguồn.
- PRODUCT_TIMEZONE_OFFSET: múi giờ dùng để hiểu "hôm nay", "tuần này",
  "tháng này" và "năm nay". Ví dụ Việt Nam là +07:00.
- PRODUCT_CHAT_PAGE_SIZE: số sản phẩm hiển thị mỗi trang trong chat.
- PRODUCT_CANDIDATE_PAGE_SIZE: số sản phẩm ứng viên tối đa khi
  Client cần lọc thêm theo tên, loại hoặc tồn kho.
- AI_PROVIDER: provider mặc định, chỉ nhận gemini hoặc openai.
- AI_FALLBACK_PROVIDER: provider dự phòng cho request không chọn provider cụ thể.
- GEMINI_MODEL/OPENAI_MODEL: model thực tế mà key có quyền sử dụng.
- LLM_TIMEOUT_SECONDS: timeout cho một lượt gọi LLM.

Không dùng dạng sai sau:

  LLM_API_KEY=GEMINI_API_KEY=abc...

Mỗi dòng chỉ có một tên biến:

  GEMINI_API_KEY=abc...


6. CHỌN GEMINI HOẶC OPENAI TRÊN GIAO DIỆN
------------------------------------------

Endpoint GET /api/ai/providers trả về id, nhãn, model và trạng thái available;
không trả API key.

- Provider có API key hợp lệ sẽ chọn được trong ô nhập câu hỏi.
- Provider thiếu key hiển thị “chưa cấu hình” và bị vô hiệu hóa.
- Frontend gửi ai_provider trong từng request POST /api/chat.
- Khi người dùng đã chọn provider, backend dùng đúng provider đó và không tự đổi
  sang provider còn lại.
- AI_FALLBACK_PROVIDER chỉ dùng cho client cũ hoặc request không gửi ai_provider.
- Lựa chọn trên giao diện được lưu trong localStorage của trình duyệt.

Sau khi đổi key/model trong .env, phải khởi động lại backend và tải lại trang.

8. KIỂM TRA SAU KHI KHỞI ĐỘNG
-----------------------------

Health là endpoint công khai và chỉ xác nhận Client Backend đã chạy:

  Invoke-RestMethod http://127.0.0.1:8100/api/health

Các endpoint provider, taxonomy, tài liệu, sản phẩm, chat và quản trị đều yêu
cầu cookie đăng nhập. Chạy smoke check để kiểm tra đúng luồng thật mà không ghi
mật khẩu vào command history:

  .\.venv\Scripts\python.exe smoke_check.py --username <tai-khoan-admin>

Linux:

  .venv/bin/python smoke_check.py --username <tai-khoan-admin>

Thêm --skip-products nếu môi trường chưa đồng bộ kho sản phẩm. Smoke check xác
nhận cookie phiên, RAG, provider, taxonomy, tài liệu, sản phẩm và API quản trị.

Kiểm tra thủ công trên giao diện:

- Danh sách loại và nhóm tài liệu tải được.
- Có thể chọn phạm vi tài liệu.
- Có thể chọn Gemini/OpenAI đã cấu hình.
- Câu trả lời hiển thị Markdown, bảng và nguồn [Sx].
- “Tài liệu tham khảo” mở được tài liệu nguồn.
- Ảnh nguồn tải qua /api/rag-assets/{id} nếu RAG trả sources[].assets.
- Không thấy API key trong DevTools -> Network hoặc mã JavaScript.

11. TRIỂN KHAI PRODUCTION TRÊN VPS/LINUX
-----------------------------------------

Kiến trúc khuyến nghị:

  Internet -> HTTPS/Nginx -> 127.0.0.1:8100 RAG Client
                               -> RAG Server trong mạng nội bộ
                               -> Gemini/OpenAI qua HTTPS

Chuẩn bị:

  sudo mkdir -p /opt/rag-client-ui
  sudo chown <LINUX_USER>:<LINUX_GROUP> /opt/rag-client-ui
  cd /opt
  git clone https://github.com/PhucDhcntt4/rag-client-ui.git rag-client-ui
  cd /opt/rag-client-ui/backend
  python3 -m venv .venv
  .venv/bin/python -m pip install --upgrade pip
  .venv/bin/pip install -r requirements.txt
  cp .env.example .env

Điền key thật vào /opt/rag-client-ui/backend/.env rồi chạy test.

Chạy thử production, không dùng --reload:

  .venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8100 --workers 2

Tạo /etc/systemd/system/rag-client-ui.service:

  [Unit]
  Description=RAG Client UI
  After=network-online.target
  Wants=network-online.target

  [Service]
  Type=simple
  User=<LINUX_USER>
  Group=<LINUX_GROUP>
  WorkingDirectory=/opt/rag-client-ui/backend
  Environment=PYTHONUNBUFFERED=1
  ExecStart=/opt/rag-client-ui/backend/.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8100 --workers 2
  Restart=always
  RestartSec=5
  TimeoutStopSec=30

  [Install]
  WantedBy=multi-user.target

Kích hoạt:

  sudo systemctl daemon-reload
  sudo systemctl enable --now rag-client-ui
  sudo systemctl status rag-client-ui

Xem log:

  sudo journalctl -u rag-client-ui -f


12. CẤU HÌNH NGINX VÀ HTTPS
----------------------------

Ví dụ server block:

  server {
      listen 80;
      server_name chat.example.com;

      client_max_body_size 2m;

      location / {
          proxy_pass http://127.0.0.1:8100;
          proxy_http_version 1.1;
          proxy_set_header Host $host;
          proxy_set_header X-Real-IP $remote_addr;
          proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
          proxy_set_header X-Forwarded-Proto $scheme;
          proxy_connect_timeout 10s;
          proxy_read_timeout 180s;
          proxy_send_timeout 180s;
      }
  }

Kiểm tra và reload:

  sudo nginx -t
  sudo systemctl reload nginx

Bật HTTPS bằng chứng chỉ phù hợp, sau đó sửa backend/.env:

  APP_ENV=production
  FRONTEND_ORIGIN=https://chat.example.com

Khởi động lại:

  sudo systemctl restart rag-client-ui


13. KHI RAG SERVER CHẠY Ở MÁY HOẶC CONTAINER KHÁC
-------------------------------------------------

- Cùng máy: RAG_BASE_URL=http://127.0.0.1:8000
- Khác máy: dùng IP nội bộ hoặc domain HTTPS truy cập được từ Client Backend.
- Docker: 127.0.0.1 là chính container Client; dùng tên service, ví dụ
  RAG_BASE_URL=http://rag-service:8000.
- Không đặt URL máy cá nhân nếu Client chạy trên VPS/Vercel.
- Kiểm tra firewall, DNS và chứng chỉ TLS từ chính máy chạy Client Backend.
- Không mở RAG Server công khai nếu không cần; luôn giữ Bearer authentication.


14. VERCEL
----------

Dự án hiện tối ưu cho VPS hoặc máy chủ chạy FastAPI liên tục, chưa phải cấu trúc
Vercel serverless hoàn chỉnh. Không thể chỉ import repository và mong đợi Uvicorn
chạy thường trực.

Muốn dùng Vercel cần bổ sung entrypoint Python serverless và vercel.json, đồng
thời kiểm tra giới hạn thời gian request. RAG_BASE_URL phải là URL HTTPS mà Vercel
truy cập được; 127.0.0.1:8000 trên máy cá nhân không có tác dụng. Khai báo mọi
biến trong Vercel Project Settings, không tải backend/.env lên Git.

Với lượt chat gồm cả RAG và LLM, VPS/Render/Railway/Fly.io hoặc một container
service thường phù hợp hơn môi trường serverless có timeout ngắn.

16. XỬ LÝ LỖI THƯỜNG GẶP
-------------------------

Lỗi: ModuleNotFoundError: No module named 'app'

- Nguyên nhân: chạy Uvicorn ngoài thư mục backend.
- Sửa: cd vào backend rồi chạy uvicorn app.main:app ...

Lỗi: ValidationError khi khởi động

- Kiểm tra backend/.env tồn tại.
- Kiểm tra RAG_BASE_URL, RAG_SEARCH_API_KEY và RAG_ADMIN_API_KEY.
- AI_PROVIDER chỉ nhận gemini hoặc openai.
- Không để AI_FALLBACK_PROVIDER thành chuỗi rỗng; comment dòng nếu không dùng.
- Không viết hai tên biến trên cùng một dòng.

Lỗi: /api/health chạy nhưng taxonomy/chat lỗi

- /api/health chỉ kiểm tra Client Backend, không kiểm tra RAG hoặc LLM.
- Kiểm tra RAG Server /health/live, RAG_BASE_URL, key và firewall.

Lỗi: 401/403 từ RAG Server

- RAG_SEARCH_API_KEY hoặc RAG_ADMIN_API_KEY sai/hết hạn/không đủ quyền.
- Không dùng placeholder replace-with-... trong production.

Lỗi: 503 Không thể kết nối RAG Service

- RAG Server chưa chạy, URL sai, DNS/firewall lỗi hoặc timeout.
- Nếu chạy Docker, không dùng 127.0.0.1 cho container khác.

Lỗi: Gemini/OpenAI hiện “chưa cấu hình”

- Điền GEMINI_API_KEY hoặc OPENAI_API_KEY rồi restart backend.
- Mở GET /api/ai/providers để xem available.
- Tải lại trang bằng Ctrl+F5.

Lỗi: 503 từ LLM

- Kiểm tra AI provider được chọn, API key, model, quota và kết nối Internet.
- Kiểm tra kết nối Internet tới API của provider.
- Model phải tồn tại và key phải có quyền gọi model.

Lỗi: trả lời có dấu ** thay vì hiển thị đậm hoặc bảng không format

- Kiểm tra frontend/assets/marked.js được tải thành công.
- Kiểm tra DevTools Console và Network.
- Không xóa MARKED_LICENSE.md khi phân phối marked.js.

Lỗi: ảnh nguồn không hiển thị

- Kiểm tra response chat có sources[].assets.
- Kiểm tra GET /api/rag-assets/{id}.
- Kiểm tra RAG_SEARCH_API_KEY có quyền tải asset.
- PDF cũ có thể cần upload lại bằng đúng source_key để tạo asset.

Lỗi: OpenAI dồn hàng loạt nguồn ở cuối

- Code hiện tự loại chuỗi từ 6 nhãn nguồn liên tiếp trở lên với OpenAI.
- Restart backend và tạo cuộc trò chuyện mới để tránh lịch sử cũ ảnh hưởng.


17. BẢO MẬT
------------

- backend/.env đã nằm trong .gitignore; vẫn phải kiểm tra trước khi commit.
- Không đặt key trong frontend, ảnh chụp, tài liệu công khai hoặc log.

- Chỉ cấp đúng quyền cần thiết cho RAG search/admin key.
- Dùng HTTPS cho production.
- Giới hạn SSH, firewall và quyền đọc backend/.env.
- Không trả stack trace hoặc cấu hình bí mật cho người dùng cuối.
- Định kỳ xoay key và kiểm tra quota của Gemini/OpenAI.

Kiểm tra file .env có bị Git theo dõi không:

  git check-ignore -v backend/.env

19. TÌM SẢN PHẨM BẰNG ẢNH
---------------------------

- Pipeline hiện tại: OpenCLIP tìm nhanh -> Qdrant toàn catalog -> Fast Accept;
  nếu chưa chắc chắn thì Gemini Vision xác định bounding box -> crop ->
  OpenCLIP lại -> Qdrant toàn catalog + theo product_type -> Gemini Visual
  Verification -> Decision Engine -> RAG Service lấy chi tiết và tồn kho.
- Model phải giống kho vector: ViT-B-32 / laion2b_s34b_b79k / 512 chiều.
- Qdrant phải truy cập được từ máy chạy Client Backend.
- Không mở Qdrant cho trình duyệt hoặc đưa QDRANT_API_KEY vào JavaScript.
- RAG Service vẫn phải chạy để Client lấy chi tiết, giá, size và tồn kho
  sau khi Qdrant trả về product_code.
- Lần tìm ảnh đầu tiên có thể chậm hơn do OpenCLIP được nạp lazy.
- Endpoint: POST /api/products/image-search, multipart field: file.
- Hỗ trợ JPEG, PNG, WebP; dung lượng do PRODUCT_IMAGE_MAX_BYTES quyết định.
- Chỉ tối đa PRODUCT_VISION_VERIFY_TOP_K ảnh tham chiếu được gửi tới Gemini.
- Danh sách kiểm chứng luôn giữ lại một số ứng viên phù hợp nhóm
  sản phẩm từ ảnh gốc. Việc này tránh làm mất SKU đúng khi crop
  ảnh làm thay đổi thứ hạng vector.
- Prompt phân tích và prompt kiểm chứng nằm riêng trong backend/app/prompts.
- Nếu Gemini, ảnh tham chiếu hoặc truy vấn theo nhóm lỗi, hệ thống fallback
  về kết quả Qdrant thay vì làm hỏng toàn bộ request.
- PyTorch/OpenCLIP không phù hợp Vercel Functions; nên dùng VPS, Docker,
  Render hoặc máy chủ có bộ nhớ đủ lớn.

Cấu hình chính:

  PRODUCT_VISION_ENABLED=true
  PRODUCT_VISUAL_VERIFICATION_ENABLED=true
  PRODUCT_VISION_VERIFY_TOP_K=5
  PRODUCT_VISION_ORIGINAL_CANDIDATE_SLOTS=2
  PRODUCT_IMAGE_FAST_ACCEPT_SCORE=0.88
  PRODUCT_IMAGE_FAST_ACCEPT_MARGIN=0.08
  PRODUCT_IMAGE_VECTOR_WEIGHT=0.55
  PRODUCT_IMAGE_VISUAL_WEIGHT=0.45
  PRODUCT_IMAGE_VERIFY_MIN_SCORE=0.65
  PRODUCT_IMAGE_VISUAL_MIN_SCORE=0.50
  PRODUCT_IMAGE_HIGH_CONFIDENCE=0.82
  PRODUCT_IMAGE_MEDIUM_CONFIDENCE=0.65
  PRODUCT_REFERENCE_IMAGE_TIMEOUT_SECONDS=15
  PRODUCT_REFERENCE_IMAGE_MAX_BYTES=6291456

Kiểm tra Qdrant:

  collection phải green
  vector size phải là 512
  distance phải là Cosine

Kiểm thử giao diện:

  1. Bật Qdrant và RAG Service port 8000.
  2. Chạy Client Backend port 8100.
  3. Bấm Tìm bằng ảnh và chọn ảnh catalog.
  4. Kiểm tra mã đúng nằm ở vị trí đầu, album hiển thị và link sản phẩm mở được.


20. QUẢN TRỊ NHÓM QUYỀN TÀI LIỆU
---------------------------------

Khởi tạo hoặc nâng cấp schema (lệnh có thể chạy lại):

  cd backend
  python -X utf8 init_db.py

Mô hình quyền:

- Mỗi user chỉ có một permission_group_id trong rag_client.users.
- Một nhóm quyền có thể được cấp toàn bộ tài liệu, một doc_type (mục cha), hoặc
  từng document_group (mục con).
- Không gán nhóm hoặc nhóm đã bị khóa đồng nghĩa user không được truy cập tài liệu.
- Admin luôn có toàn quyền tài liệu và là role duy nhất được gọi /api/admin/*.
- Backend lọc cả taxonomy, danh sách/chi tiết tài liệu, kết quả chat và ảnh tài liệu;
  việc ẩn nút trên frontend không được dùng thay cho kiểm tra quyền backend.

Sử dụng giao diện:

  1. Đăng nhập bằng tài khoản role=admin.
  2. Bấm nút hình khiên trên header.
  3. Tạo hoặc chọn nhóm quyền.
  4. Chọn mục cha/mục con rồi bấm Lưu phạm vi tài liệu.
  5. Trong danh sách người dùng, chọn đúng một nhóm cho từng tài khoản.
  6. Đăng nhập bằng tài khoản thường để kiểm tra taxonomy và câu trả lời chỉ còn
     dữ liệu thuộc phạm vi vừa cấp.

Endpoint quản trị:

- GET  /api/admin/permission-groups
- POST /api/admin/permission-groups
- PUT  /api/admin/permission-groups/{group_id}
- DELETE /api/admin/permission-groups/{group_id}
- PUT  /api/admin/permission-groups/{group_id}/scopes
- GET  /api/admin/users
- POST /api/admin/users
- PUT  /api/admin/users/{user_id}
- PUT  /api/admin/users/{user_id}/password
- PUT  /api/admin/users/{user_id}/permission-group

Nếu frontend chạy khác origin với backend, CORS phải cho phép GET, POST, PUT và
DELETE; request phải gửi cookie bằng credentials=include.
